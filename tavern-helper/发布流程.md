# 预设助手发布流程

当前发布版本：`0.41.5`

## 版本规则

- 可见版本写在 `预设助手/changelog.ts` 的 `CURRENT_CHANGELOG_VERSION` 中。
- 版本固定使用 `v0.41.X`；日常发布只递增 `X`，没有明确要求时禁止修改 `0.41`。
- 用户更新日志与脚本发布版本相互独立；没有用户明确要求时，禁止修改或新增 `changelog.ts` 中的日志。
- 构建文件使用 `file/index-版本号.js`，例如 `file/index-0.41.5.js`。
- 已发布文件不覆盖；每次更新递增版本并创建新文件，避免酒馆和 CDN 命中旧缓存。
- 标签、源码版本和构建文件名必须一致。

## 1. 更新版本与日志

确认下一个脚本发布号，只递增 `X`。仅在用户明确提供或要求日志内容时，才修改 `预设助手/changelog.ts`。

## 2. 检查并生产构建

在 Tavern Helper Template 项目根目录执行：

```powershell
pnpm exec eslint "src/util/酒馆助手脚本/预设助手"
pnpm build
```

生产构建位于：

```text
dist/util/酒馆助手脚本/预设助手/index.js
```

公开发布必须使用 `pnpm build` 的生产产物，不使用 `pnpm build:dev`。

## 3. 同步发布仓库

将生产构建复制为新的版本文件，例如：

```powershell
Copy-Item `
  "dist/util/酒馆助手脚本/预设助手/index.js" `
  "riyuexi/file/index-0.41.5.js"
```

同时将最新的 `预设助手` 源码目录同步到本仓库的 `tavern-helper/预设助手/`。

## 4. 提交、打标签并推送

在 `riyuexi` 仓库内执行：

```powershell
git add README.md file/index-0.41.5.js tavern-helper
git commit -m "release: preset helper v0.41.5"
git tag -a v0.41.5 -m "Preset Helper v0.41.5"
git push origin main
git push origin v0.41.5
```

`ads_v4.json` 不属于预设助手发布范围，不修改也不加入版本提交。

## 5. 酒馆助手导入地址

推荐使用固定版本标签，便于回滚：

```js
import "https://cdn.jsdelivr.net/gh/colerith/riyuexi@v0.41.5/file/index-0.41.5.js";
```

也可以跟随 `main`，但每次仍需使用新的文件名绕过缓存：

```js
import "https://cdn.jsdelivr.net/gh/colerith/riyuexi@main/file/index-0.41.5.js";
```

发布后先访问对应 jsDelivr 地址，确认返回 JavaScript 而不是 404，再在酒馆中停用并重新启用导入脚本。
